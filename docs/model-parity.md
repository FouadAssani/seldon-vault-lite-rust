# Numerical parity and reference datasets

## Status

At milestone M2, the text encoder of `google/embeddinggemma-2` is implemented
in FP32 scalar Rust and verified against the official Transformers
implementation. The model is frozen at revision
`f9972ac22e696a105c482202646979e33e4b5a1e`. Tokenization parity, text
embeddings at 768/512/256/128 dimensions, intermediate layer outputs, and the
final 512 to 768 projection are covered by committed fixtures.

At milestone M4, the official image preprocessing and the Gemma 4 vision tower
are implemented and verified against the official reference. Image-only
embeddings are produced in the shared 768-dimensional space. Text-to-image and
image-to-image ranking are validated on a two-image reference corpus, and image
documents are stored, indexed, and searched through the CLI. Broader ranking
quality remains future work.

At milestone M5, the native WAV decoder, the official Gemma 4 audio log-mel
preprocessing, and the Gemma 4 audio tower are implemented and verified against
the official reference. Audio-only embeddings are produced in the same
768-dimensional space as text and images. Text-to-audio and audio-to-audio
ranking are validated on a six-clip reference corpus, and audio documents are
stored, indexed, and searched through the CLI. MP3, streaming audio, and broader
audio ranking quality remain future work and are not claimed.

At milestone M7, runtime-selected NEON kernels were added for the shared
kernels, with differential scalar-vs-NEON tests and a replay of the frozen text,
image, and audio parity suites. No tolerance was relaxed.

At milestone M8, the numerical paths are unchanged. The release gate replays
the frozen parity suites and runs the clean-environment lifecycle harness; it
does not introduce a new numerical claim. The release documentation records the
same tolerances and the same frozen model revision.

## Principle

The official `google/embeddinggemma-2` implementation serves as a reference
**in the laboratory only**. It is not part of the product, is not a Cargo
dependency, and is never launched by the delivered binary.

Golden tests are produced outside the product, then frozen in `fixtures/` in
compact form. The product only reads these fixtures and compares its outputs.

The M2 and M4 reference runs used Python 3.13, PyTorch 2.15.0 CPU, and
Transformers 5.22.2 in float32. The model card recommends bfloat16 or float32
and forbids float16. The reference used float32 so that the FP32 scalar Rust
path is compared with the closest official numerical configuration.

The official Gemma4ImageProcessor depends on torchvision, which was not
installed in the reference environment. The image goldens therefore reproduce
its tensor operations directly with torch.nn.functional.interpolate (bicubic,
antialias, align_corners false) on uint8 tensors, the float RGBA composite, and
the documented aspect-ratio and patchification logic. The generator is
scripts/generate_image_goldens.py; it is laboratory-only.

## Model manifest

The model is frozen at revision `f9972ac22e696a105c482202646979e33e4b5a1e`.
The manifest is `fixtures/model/manifest.json` (schema version 1). It records:

- the repository, exact revision, source URL, freeze date, and license;
- every file used (config, tokenizer, processors, prompts) with its size and
  SHA-256;
- the text configuration and tokenizer inventory;
- the provenance of the fixtures and the tool that generated them;
- the manifest schema version.

Giant weights are never committed. The weights' SHA-256 is the Hugging Face
LFS object id; the file is a development asset outside Git. Model files live in
`.model-cache/<revision>/`, which is ignored by Git.

## Fixtures

Rules:

- compact size; prefer excerpts and reduced tensors;
- explicit provenance: model, revision, generation script, date;
- SHA-256 fingerprint of each fixture file;
- no personal data, no secrets;
- no complete weights, no multi-gigabyte file;
- stable, versioned naming.

At M2:

- `fixtures/model/text_golden.json` (schema version 2) holds eight text
  cases and one layer probe generated by the official implementation;
- `fixtures/model/tiny_text/` is a complete 3-layer EmbeddingGemma 2 text
  model generated with the official code, its configuration, and its golden
  layer outputs and embedding;
- `fixtures/tokenizer/golden.json` holds token ids produced by the official
  tokenizer;
- `fixtures/tokenizer/mini_tokenizer.json` reproduces the full tokenizer on
  the golden corpus;
- `fixtures/formats/mini.safetensors` proves format handling;
- `fixtures/model/manifest.json` records the frozen model and fixture
  fingerprints.

PNG and baseline JPEG decoder fixtures were added at M4. They prove decoder
behavior and corruption handling only.

M4 also adds two reference fixtures:

- fixtures/media/preprocess_golden.json records the official resized bytes,
  padded patch values, and positions for nine images at the 70 or 280 token
  budget, including rotations and non-square aspect ratios, with SHA-256
  fingerprints;
- fixtures/model/image_golden.json records the patch embedder probe, all 16
  vision layer probes, the projected vision soft tokens, the input token ids,
  and the final normalized image embedding for seven images, including a
  rotation and a non-square aspect ratio.

The image fixtures are generated outside the product with Transformers 5.22.2
and PyTorch 2.15.0 CPU in float32.

M5 adds:

- fixtures/media/audio/ contains six short WAV excerpts: silence, a short tone,
  a long tone, French speech, a music chord progression, and rain-like noise.
  The synthetic clips were generated with deterministic Python code; the French
  speech was generated with the macOS `say` French voice and converted to
  16 kHz mono PCM. The exact generation commands are recorded in
  fixtures/media/README.md.
- fixtures/media/audio_preprocess_golden.json records the official mel-frame
  count, valid-frame count, padded sample count, feature fingerprint, and first
  feature values for every clip;
- fixtures/model/audio_golden.json records the audio token layout, SSCP output
  probe, all 12 encoder layer probes, the projected audio features, and the
  final normalized audio embedding for every clip.
- fixtures/model/tiny_audio/ is a complete small composite model generated with
  the official code: the committed tiny text weights plus a deterministic
  two-layer audio tower with hidden 16, two heads of dimension 8, subsampling
  channels [128, 8], chunk size 2, left context 3, and output projection 16.
  Its golden records a deterministic 12-frame sine input, the official log-mel
  features and mask, the SSCP output, both layer outputs, the projected audio
  features, and the final normalized 8-dimensional embedding. The Rust test
  runs without the frozen model cache and covers the audio configuration,
  weight loader, SSCP, chunked attention, light convolution, feed-forward
  branches, projection, and text connection.

The audio fixtures are generated outside the product with Transformers 5.22.2
and PyTorch 2.15.0 CPU in float32. The laboratory generator is
scripts/generate_audio_goldens.py; it is never run by the product.

## Tokenization parity

Token ids must match the official tokenizer exactly; any divergence blocks
inference integration.

- Golden ids were generated outside the product with `tokenizers 0.23.3` and
  the frozen `tokenizer.json`.
- The corpus covers empty input, English, accented French, code, emoji, Greek,
  Japanese, Arabic, leading and multiple spaces, newlines and tabs, special
  tokens, rare Unicode byte fallback, a long text, and a repeated-character
  stress case.
- The reduced tokenizer fixture preserves original token ids and reproduces the
  full tokenizer exactly on the corpus.
- When `.model-cache` is present, the parity test verifies the full
  tokenizer's SHA-256 against the manifest and replays every case.
- The text golden cases also compare prompt-prefixed token ids against the
  official tokenizer.

## Text architecture parity

The M2 forward pass reproduces the official encoder:

- scaled token embeddings;
- projection-only per-layer embeddings (PLE), scaled, reshaped, and normalized;
- 24 bidirectional layers with sliding attention (radius 512) and full
  attention on layers 5, 11, 17, and 23;
- grouped-query attention (2 key/value heads for sliding layers, 1 for full
  layers);
- per-head query and key RMSNorm with learned weights, and a value RMSNorm
  without a learned scale;
- layer-specific RoPE with theta 10,000 for sliding layers and 1,000,000 for
  full layers;
- attention scale 1.0;
- gated GELU feed-forward blocks;
- the PLE residual block and the per-layer scalar;
- final RMSNorm, 512 to 768 projection, mean pooling over all tokens (prompt
  included), and L2 normalization;
- Matryoshka truncation to 768, 512, 256, and 128 dimensions followed by a
  second L2 normalization.

The layer probe stores the scaled embedding output, all 24 layer outputs, and
the final projected state for a short text. It lets a regression be localized
to a layer rather than only observed in the final vector.

## Image preprocessing parity

The M4 preprocessing pipeline reproduces the official Gemma4 processor:

- RGB conversion: grayscale replicated, RGBA composited over white with the
  float path and half-to-even rounding;
- aspect-ratio preserving target size, with both sides multiples of 48;
- antialiased bicubic resize on uint8 tensors, using separable horizontal then
  vertical passes, Keys cubic convolution with a = -0.5, per-output normalized
  weights, and 16-bit fixed-point accumulation;
- rescaling by 1/255;
- 16x16 patchification in pixel-major, channel-last order;
- padded (x, y) positions with (-1, -1) for padding.

The committed preprocessing goldens compare the resized bytes, the padded
patch values, and the positions by SHA-256. The Rust implementation matches
them exactly for grayscale, RGB, RGBA, gradient, and quadrant fixtures at the
70 and 280 token budgets. The 2x2 RGB case at the default budget is 768x768
with 2,304 real patches and 256 soft tokens, so the official processor
upscales small inputs rather than preserving their original size.

## Image architecture parity

The M4 vision tower reproduces the frozen gemma4_vision configuration:

- patch projection over 3*16*16 values;
- learned two-axis position embeddings, summed and zeroed for padding;
- 16 bidirectional layers, 12 query and 12 key/value heads of dimension 64,
  attention scale 1.0;
- query and key RMSNorm with learned weights, unscaled value RMSNorm;
- axial 2-D RoPE with theta 100 and the H-H-W-W layout;
- gated GELU feed-forward with tanh approximation;
- 3x3 average pooling, sqrt(768) scaling, RMSNorm without a scale, and the
  768 to 512 projection;
- the image-only prompt <bos><|image><|image|>*soft<image|><eos>, PLE from the
  final inputs_embeds including vision features, mean pooling over every token,
  the 512 to 768 projection, L2 normalization, and Matryoshka truncation.

Only real patches are processed. The reference masks padding keys in attention
and discards padding queries in the pooler, so compressing the padding away is
mathematically equivalent. The image layer probe stores the patch embedder
output and all 16 encoder layer outputs for the first real patch; the full
tensor fingerprints remain in the fixture for manual inspection.

## Audio preprocessing parity

The M5 audio pipeline reproduces the official Gemma4AudioFeatureExtractor:

- 16 kHz mono input;
- 320-sample frames (20 ms) and a 160-sample hop (10 ms);
- periodic Hann window `0.5 - 0.5 cos(2πn/320)`;
- 160 zeros of semicausal left padding; the 321-sample analysis window drops
  its last sample in the no-preemphasis branch;
- 512-point real FFT, 257 magnitude bins;
- 128 HTK mel filters from 0 Hz to 8000 Hz, no area normalization, floor
  0.001, natural logarithm;
- right-padding to a multiple of 128 samples;
- a frame mask that marks only frames whose complete analysis window contains
  real audio; invalid frames are exactly zero.

The committed preprocessing goldens compare the padded sample count, mel-frame
count, valid-frame count, and first feature values. The FFT and mel projection
use f64 accumulation and round to f32 once. The path is not claimed bit-exact
because a different radix-2 FFT can differ in the last f32 bit; the observed
maximum absolute difference on the short reference clip is `4.77e-7` and the
mean absolute difference is `1.65e-8`.

## Audio architecture parity

The M5 audio tower reproduces the frozen gemma4_audio configuration:

- two 3x3 convolution layers with stride 2, padding 1, no bias, channel
  LayerNorm with a learned weight and no bias, and ReLU; the time mask is
  strided by two after each layer;
- flattening in [time, frequency, channel] order and a linear projection to
  hidden 1024;
- sinusoidal relative positions `[sin..., cos...]` for positions
  `context_size/2 ... 0`, projected by a per-layer `relative_k_proj`;
- 12 chunked-local-attention layers: blocks of 12 queries, left context 13,
  right context 0, distances 0..11, per-head scores
  `q·k + q·relative_key`, query scale `1/sqrt(head_dim)/ln 2` times
  `softplus(per_dim_scale)`, key scale `ln(1+e)/ln 2`, logit soft cap
  `tanh(score/50)*50`, and per-head softmax;
- clipped linear layers with the frozen input/output bounds;
- a causal depthwise light convolution (kernel 5) with RMSNorm, GLU, RMSNorm,
  SiLU, and a clipped linear, plus a residual;
- two feed-forward branches with RMSNorm, clipped linear to 4h, SiLU, clipped
  linear to h, RMSNorm, residual weight 0.5, and a residual;
- layer order: feed_forward1, pre-attention norm, attention, post-attention
  norm plus residual, light convolution, feed_forward2, output norm;
- a 1024 to 1536 output projection with bias, an unscaled RMSNorm, and a
  1536 to 512 projection;
- the audio-only prompt <bos><|audio><|audio|>*soft<audio|><eos>, PLE from the
  final inputs_embeds including audio features, mean pooling over every token,
  the 512 to 768 projection, L2 normalization, and Matryoshka truncation.

Padding queries are skipped; the tower is causal along time, so trailing
padding cannot influence a valid query. The audio layer probe stores the SSCP
output and all 12 encoder layer outputs over valid soft tokens; the full tensor
fingerprints remain in the fixture for manual inspection.

The committed audio golden covers silence, a short tone, a long tone, French
speech, a music chord progression, and rain-like noise. The tiny audio fixture test
runs by default without the frozen model cache; the short-tone parity test runs
when the cache is present; the full six-case test and the text-to-audio ranking
test are ignored because they load the frozen model and embed several clips.

## Mandatory coverage

Golden tests cover at least:

- accented French, English, source code;
- empty string, Unicode, emoji;
- the official SearchQuery, Document, Classification, Clustering, and
  SentenceSimilarity prompts;
- dimensions 768, 512, 256, and 128, with renormalization after truncation;
- intermediate layer outputs and the final projection;
- a query and an indexed document, kept distinct by their prefixes.

Image decoder coverage exists for PNG and baseline JPEG. Image preprocessing
coverage exists for grayscale, RGB, RGBA, gradient, quadrant, rotation, and
non-square aspect-ratio fixtures at the 70 and 280 token budgets. Image
embedding coverage exists for seven fixtures at the 70 and 280 token budgets,
including a 90-degree rotation and a 2:1 aspect ratio. The CLI index and vector-search path is exercised end to end
with one indexed image and a text query: the image document is stored with
modality image, found by exact vector search, and returned with its source.
A two-image ranking test indexes a colorful quadrant image and a grayscale
image. The text query "a colorful four-quadrant test pattern" ranks the
quadrant image first and the grayscale image second. An image query with the
quadrant image ranks the identical image first and the grayscale image second.
Both queries return modality image. The ignored rotation/aspect vision test
reproduces the official probes and final embeddings for a 90-degree rotation
and a 2:1 aspect-ratio image. Broader text-to-image and image-to-image ranking
quality on a larger corpus remains future work; M4 is complete for the
committed reference corpus.

M5 adds WAV decoder coverage for PCM 8/16/24/32, IEEE float 32, stereo downmix,
malformed and truncated headers, unsupported codecs, non-finite samples, and
resampling behavior. Audio preprocessing coverage exists for six clips: silence,
a short tone, a long tone, French speech, music, and rain-like noise. Audio
embedding coverage exists for the same six clips, with all 12 layer probes and
the final normalized embedding. The ignored six-case parity test reproduces the
official outputs. The ignored text-to-audio ranking test embeds the six clips
and three text queries; the expected top hits are rain-like noise for "rain
falling" (cosine 0.7056), the music chord progression for "music" (0.7181), and
French speech for "a test of audio search" (0.7707). An ignored CLI test indexes
three audio documents, finds the rain clip with a text query, and finds the
music clip with an audio query. Broader audio ranking quality, MP3, and
streaming audio remain future work.

## Tolerances

| Object | Comparison | Enforced tolerance |
|---|---|---|
| Token IDs | exact equality | no divergence accepted |
| Dimensions and shapes | exact equality | no divergence accepted |
| Preprocessing tensors | SHA-256 equality | exact bytes |
| Vision layer probes | absolute + relative | atol <= 5e-5, rtol <= 5e-4 |
| Image embeddings | cosine + absolute | cos >= 0.99999, atol <= 1e-4 after L2 normalization |
| Audio mel features | absolute (first values) | atol <= 1e-5 |
| Audio SSCP/layer/feature probes | absolute + relative | atol <= 2e-4, rtol <= 2e-4 |
| Audio embeddings | cosine + absolute | cos >= 0.999, atol <= 2e-3 after L2 normalization |
| Intermediate FP32 tensors | absolute + relative | `atol <= 2e-5`, `rtol <= 1e-4` |
| Projected FP32 states | absolute + relative | `atol <= 2e-4`, `rtol <= 1e-4` |
| Final FP32 embeddings | cosine + absolute | `cos >= 0.9999`, `atol <= 1e-4` after L2 normalization |
| Quantized embeddings (future) | cosine + recall | `cos >= 0.999`, `recall@10 >= 0.99` against the FP32 oracle |
| FP32 search ranking | rank | identical top-1, `recall@10 = 1.0` on the reference corpus |
| Quantized search ranking | rank | `recall@10 >= 0.99` against the FP32 oracle |

NaN and infinities are forbidden in expected outputs. A tolerance must never
hide a tokenization, dimension, or prompt error.

The vision layer tolerance is wider than the text layer tolerance because the
16-layer scalar tower accumulates more rounding error, and the release build
reorders some scalar expressions. The measured maximum divergence on the
frozen probe is about 3.7e-4 on a large activation; the final image embedding
remains within 1e-4 and above 0.99999 cosine in both test and release builds.

The projected-state tolerance is wider than the layer tolerance because the
512 to 768 projection accumulates 512 products and the reference matrix
multiplication uses a different accumulation order. The measured maximum
divergence on the frozen probe is about `1.2e-4` on one component; the final
normalized embedding remains within `1e-4` and above `0.9999` cosine for every
case. The wider bound applies only to the unnormalized diagnostic state, never
to the product embedding.

The audio tolerances are wider than the text tolerances because the tower has
two convolution stages, 12 layers of chunked attention, and a 1536-dimensional
projection. The short-tone parity test compares SSCP, every layer probe, and the
projected features at `2e-4` absolute and relative, and the final embedding at
cosine `0.999` and maximum absolute difference `2e-3`. The full six-case test
passes with those bounds in the test profile. The mel feature check uses the
first values with `1e-5` absolute tolerance because the product's radix-2 FFT
is not bit-identical to NumPy's pocketfft.

## Blocking rule

Any **token ID** divergence blocks the integration of inference layers. A layer
whose outputs exceed tolerances cannot be declared compatible, even if the
final ranking "seems" correct.

## Determinism

The FP32 scalar path is the reference. SIMD kernels and optimizations must be
compared with the scalar path before any performance measurement. Golden tests
are replayed after each optimization; a gain that breaks parity is rejected.

M7 adds a runtime-selected NEON path. Its four-lane reductions and fused
multiply-add differ from the scalar reduction order by a few units in the last
place. `src/tensor/kernels.rs` contains differential tests that compare every
NEON kernel with the scalar reference, including tail lengths and the real model
shapes. The official text, image, and audio parity suites were replayed with
their existing thresholds after the change; no threshold was loosened. The NEON
reduction order is fixed, so repeated calls remain deterministic.

The text model is immutable after loading and is `Send + Sync`. Repeated calls
with the same token ids are bit-for-bit deterministic.

## Prompts and roles

The official `SearchQuery` and `Document` prefixes are copied from
`config_sentence_transformers.json` into `model::prompt`. A query and an
indexed document are never confused; `Prompt::is_query` makes the distinction
explicit. A test compares every constant with the frozen manifest. Document
titles are preserved when the official prompt provides for it; the current
document prefix uses the official default title placeholder.

## Limits

Fixtures do not prove compatibility with all possible inputs. They prove
compliance on a documented and reproducible corpus. Robustness tests
(corruption, truncation, extreme sizes) are distinct from parity tests.

The engine rejects token sequences above the documented 8,192-token context,
out-of-vocabulary ids, empty sequences, and dimensions above the model output.
The text weights file is capped at 4 GiB and the FP32 weight set at 2^30
elements.
