# Numerical parity and reference datasets

## Status

At milestone M2, the text encoder of `google/embeddinggemma-2` is implemented
in FP32 scalar Rust and verified against the official Transformers
implementation. The model is frozen at revision
`f9972ac22e696a105c482202646979e33e4b5a1e`. Tokenization parity, text
embeddings at 768/512/256/128 dimensions, intermediate layer outputs, and the
final 512 to 768 projection are covered by committed fixtures.

Image and audio encoders are not implemented and no multimodal embedding is
claimed. The tolerances below are the values enforced by the M2 tests.

## Principle

The official `google/embeddinggemma-2` implementation serves as a reference
**in the laboratory only**. It is not part of the product, is not a Cargo
dependency, and is never launched by the delivered binary.

Golden tests are produced outside the product, then frozen in `fixtures/` in
compact form. The product only reads these fixtures and compares its outputs.

The M2 reference runs used Python 3.13, PyTorch 2.15.0 CPU, and Transformers
5.22.2 in float32. The model card recommends bfloat16 or float32 and forbids
float16. The reference used float32 so that the FP32 scalar Rust path is
compared with the closest official numerical configuration.

## Model manifest

The model is frozen at revision `f9972ac22e696a105c482202646979e33e4b5a1e`.
The manifest is `fixtures/model/manifest.json` (schema version 1). It records:

- the repository, exact revision, source URL, freeze date, and license;
- every file used (config, tokenizer, processors, prompts) with its size and
  SHA-256;
- the text configuration and tokenizer inventory;
- the provenance of the fixtures and the tool that generated them;
- the manifest schema version.

Giant weights are never committed. The weights' SHA-256 is the Hugging Face
LFS object id; the file is a development asset outside Git. Model files live in
`.model-cache/<revision>/`, which is ignored by Git.

## Fixtures

Rules:

- compact size; prefer excerpts and reduced tensors;
- explicit provenance: model, revision, generation script, date;
- SHA-256 fingerprint of each fixture file;
- no personal data, no secrets;
- no complete weights, no multi-gigabyte file;
- stable, versioned naming.

At M2:

- `fixtures/model/text_golden.json` (schema version 2) holds eight text
  cases and one layer probe generated by the official implementation;
- `fixtures/model/tiny_text/` is a complete 3-layer EmbeddingGemma 2 text
  model generated with the official code, its configuration, and its golden
  layer outputs and embedding;
- `fixtures/tokenizer/golden.json` holds token ids produced by the official
  tokenizer;
- `fixtures/tokenizer/mini_tokenizer.json` reproduces the full tokenizer on
  the golden corpus;
- `fixtures/formats/mini.safetensors` proves format handling;
- `fixtures/model/manifest.json` records the frozen model and fixture
  fingerprints.

Media fixtures will be added at M4/M5.

## Tokenization parity

Token ids must match the official tokenizer exactly; any divergence blocks
inference integration.

- Golden ids were generated outside the product with `tokenizers 0.23.3` and
  the frozen `tokenizer.json`.
- The corpus covers empty input, English, accented French, code, emoji, Greek,
  Japanese, Arabic, leading and multiple spaces, newlines and tabs, special
  tokens, rare Unicode byte fallback, a long text, and a repeated-character
  stress case.
- The reduced tokenizer fixture preserves original token ids and reproduces the
  full tokenizer exactly on the corpus.
- When `.model-cache` is present, the parity test verifies the full
  tokenizer's SHA-256 against the manifest and replays every case.
- The text golden cases also compare prompt-prefixed token ids against the
  official tokenizer.

## Text architecture parity

The M2 forward pass reproduces the official encoder:

- scaled token embeddings;
- projection-only per-layer embeddings (PLE), scaled, reshaped, and normalized;
- 24 bidirectional layers with sliding attention (radius 512) and full
  attention on layers 5, 11, 17, and 23;
- grouped-query attention (2 key/value heads for sliding layers, 1 for full
  layers);
- per-head query and key RMSNorm with learned weights, and a value RMSNorm
  without a learned scale;
- layer-specific RoPE with theta 10,000 for sliding layers and 1,000,000 for
  full layers;
- attention scale 1.0;
- gated GELU feed-forward blocks;
- the PLE residual block and the per-layer scalar;
- final RMSNorm, 512 to 768 projection, mean pooling over all tokens (prompt
  included), and L2 normalization;
- Matryoshka truncation to 768, 512, 256, and 128 dimensions followed by a
  second L2 normalization.

The layer probe stores the scaled embedding output, all 24 layer outputs, and
the final projected state for a short text. It lets a regression be localized
to a layer rather than only observed in the final vector.

## Mandatory coverage

Golden tests cover at least:

- accented French, English, source code;
- empty string, Unicode, emoji;
- the official SearchQuery, Document, Classification, Clustering, and
  SentenceSimilarity prompts;
- dimensions 768, 512, 256, and 128, with renormalization after truncation;
- intermediate layer outputs and the final projection;
- a query and an indexed document, kept distinct by their prefixes.

Media coverage (images, WAV) is mandatory at M4/M5 and is not claimed here.

## Tolerances

| Object | Comparison | Enforced tolerance |
|---|---|---|
| Token IDs | exact equality | no divergence accepted |
| Dimensions and shapes | exact equality | no divergence accepted |
| Intermediate FP32 tensors | absolute + relative | `atol <= 2e-5`, `rtol <= 1e-4` |
| Projected FP32 states | absolute + relative | `atol <= 2e-4`, `rtol <= 1e-4` |
| Final FP32 embeddings | cosine + absolute | `cos >= 0.9999`, `atol <= 1e-4` after L2 normalization |
| Quantized embeddings (future) | cosine + recall | `cos >= 0.999`, `recall@10 >= 0.99` against the FP32 oracle |
| FP32 search ranking | rank | identical top-1, `recall@10 = 1.0` on the reference corpus |
| Quantized search ranking | rank | `recall@10 >= 0.99` against the FP32 oracle |

NaN and infinities are forbidden in expected outputs. A tolerance must never
hide a tokenization, dimension, or prompt error.

The projected-state tolerance is wider than the layer tolerance because the
512 to 768 projection accumulates 512 products and the reference matrix
multiplication uses a different accumulation order. The measured maximum
divergence on the frozen probe is about `1.2e-4` on one component; the final
normalized embedding remains within `1e-4` and above `0.9999` cosine for every
case. The wider bound applies only to the unnormalized diagnostic state, never
to the product embedding.

## Blocking rule

Any **token ID** divergence blocks the integration of inference layers. A layer
whose outputs exceed tolerances cannot be declared compatible, even if the
final ranking "seems" correct.

## Determinism

The FP32 scalar path is the reference. SIMD kernels and optimizations must be
compared with the scalar path before any performance measurement. Golden tests
are replayed after each optimization; a gain that breaks parity is rejected.

The text model is immutable after loading and is `Send + Sync`. Repeated calls
with the same token ids are bit-for-bit deterministic.

## Prompts and roles

The official `SearchQuery` and `Document` prefixes are copied from
`config_sentence_transformers.json` into `model::prompt`. A query and an
indexed document are never confused; `Prompt::is_query` makes the distinction
explicit. A test compares every constant with the frozen manifest. Document
titles are preserved when the official prompt provides for it; the current
document prefix uses the official default title placeholder.

## Limits

Fixtures do not prove compatibility with all possible inputs. They prove
compliance on a documented and reproducible corpus. Robustness tests
(corruption, truncation, extreme sizes) are distinct from parity tests.

The engine rejects token sequences above the documented 8,192-token context,
out-of-vocabulary ids, empty sequences, and dimensions above the model output.
The text weights file is capped at 4 GiB and the FP32 weight set at 2^30
elements.
