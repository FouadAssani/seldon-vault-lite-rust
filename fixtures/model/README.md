## Manifest contents

`manifest.json` is the versioned record of the frozen model:

- schema version;
- model id `google/embeddinggemma-2`;
- exact revision `f9972ac22e696a105c482202646979e33e4b5a1e`;
- source URL, freeze date, and license;
- every file in the repository tree with size, SHA-256, role, and a
  `committed: false` marker;
- tokenizer inventory: vocabulary size, merge count, byte fallback,
  normalizer, pre-tokenizer, post-processor, added tokens, and special ids;
- text configuration: layers, hidden size, embedding dimension, heads,
  sliding window, maximum positions, RMSNorm epsilon, activation, layer types,
  per-layer overrides, and RoPE parameters;
- official prompt map;
- SHA-256 of the committed fixtures.

## Text golden fixture

`text_golden.json` (schema version 2) was generated outside the product with
Transformers 5.22.2, PyTorch 2.15.0 CPU, and the frozen model in float32.

It contains eight cases:

| Case | Prompt | Text |
|---|---|---|
| `en-query` | SearchQuery | What causes the northern lights? |
| `en-document` | Document | The northern lights are caused by charged particles from the sun. |
| `fr-query` | SearchQuery | Bonjour, le monde ! Comment allez-vous ? |
| `code-query` | CodeRetrieval | `fn main() { println!("hello"); }` |
| `empty-query` | SearchQuery | empty string |
| `unicode-similarity` | SentenceSimilarity | `café 😀 日本語` |
| `classification` | Classification | This is a positive review. |
| `clustering` | Clustering | The cat sat on the mat. |

Each case records the prompt name, prefix, text, official token ids, and
normalized embeddings at 768, 512, 256, and 128 dimensions.

The layer probe uses the SearchQuery prefix and the text `hello`. It records
the scaled embedding output, all 24 layer outputs, and the final projected
state, as means and last-token vectors.

## Tiny official model

`tiny_text/` is a complete EmbeddingGemma 2 text model generated with the
official Transformers code. It has:

- 3 layers: two sliding-attention layers and one full-attention layer;
- hidden size 16, embedding dimension 8, intermediate size 32;
- 2 query heads and 1 key/value head; sliding head dimension 8, full head
  dimension 16;
- PLE dimension 8;
- sliding window radius 2;
- RoPE theta 10,000 for sliding and 1,000,000 for full;
- 56 tensors and 10,315 parameters.

`golden.json` records three token-id sequences with the scaled embedding
output, every layer output, the final projected state, and the normalized
embedding. This fixture exercises sliding and full attention, grouped-query
attention, PLE, two RoPE bases, and Matryoshka truncation without the 1.5 GB
weights. It is generated by the official implementation, not by the product.

## Image golden fixture

image_golden.json was generated outside the product on 2026-11-11 with
Transformers 5.22.2 and PyTorch 2.15.0 CPU in float32, using
scripts/generate_image_goldens.py. It covers seven of the nine images in
fixtures/media/preprocess_golden.json: rgb_2x2 at the 280-token budget;
rgba_2x2, gray_2x2, quadrants_16x16, gradient_16x16, wide_32x16, and
quadrants_16x16_rot90 at the 70-token budget. The tall and 180-degree
rotation images exercise preprocessing only.

Each case records:

- the source path and visual token budget;
- the soft-token count and the full image-only input token ids;
- the patch-embedder probe (first values) and all 16 vision layer probes;
- SHA-256 fingerprints of the full patch-embedder and layer outputs;
- the first projected vision soft-token values and the SHA-256 of the full
  projected tensor;
- the final normalized 768-dimensional image embedding and its SHA-256.

The image-only prompt is <bos><|image><|image|>*soft_tokens<image|><eos>.
The official model computes PLE from the final inputs_embeds including the
vision features, mean-pools every token, applies the 512 to 768 projection,
and L2-normalizes. The Rust test compares the probes with absolute plus
relative tolerance and the final embedding by cosine and absolute tolerance.

The fixture is model-dependent and is not a substitute for the text goldens.
The full seven-case run is an ignored test because the scalar vision tower is
expensive; the default test covers quadrants_16x16.

## Audio golden fixture

audio_golden.json was generated outside the product on 2026-11-11 with
Transformers 5.22.2 and PyTorch 2.15.0 CPU in float32, using
scripts/generate_audio_goldens.py. It covers the six 16 kHz mono clips in
fixtures/media/audio/: silence, a short tone, a long tone, French speech, a
music chord progression, and rain-like noise.

Each case records:

- the source path, source sample rate, channel count, and sample count;
- the mel-frame count, valid-frame count, and audio soft-token count;
- the full audio-only input token ids;
- the SHA-256 and first values of the full log-mel feature tensor;
- the SHA-256 and first values of the SSCP output over valid tokens;
- the SHA-256 and first values of every one of the 12 encoder layer outputs
  over valid tokens;
- the SHA-256 and first values of the projected audio soft tokens;
- the final normalized 768-dimensional audio embedding and its SHA-256.

The audio-only prompt is <bos><|audio><|audio|>*soft_tokens<audio|><eos>.
The official model computes PLE from the final inputs_embeds including the
audio features, mean-pools every token, applies the 512 to 768 projection, and
L2-normalizes. The Rust test compares the SSCP, layer, and projected probes with
absolute plus relative tolerance and the final embedding by cosine and absolute
tolerance.

The fixture is model-dependent and is not a substitute for the text or image
goldens. The full six-case run and the text-to-audio ranking test are ignored
because they load the frozen model and embed several clips; the default test
covers short_tone_100ms. The audio preprocessing golden is separate in
fixtures/media/audio_preprocess_golden.json.

## Tiny official audio model

`tiny_audio/` is a complete small composite model generated with the official
code and committed because it is 173,940 bytes, not model-scale data:

- `config.json` combines the committed tiny text configuration with a
  two-layer Gemma 4 audio configuration: hidden 16, two heads of dimension 8,
  subsampling channels [128, 8], chunk size 2, left context 3, right context 0,
  output projection 16, residual weight 0.5, finite clipping bounds, and SiLU.
- `model.safetensors` contains the committed tiny text weights plus a
  deterministic random audio tower and the audio-to-text projection.
- `golden.json` records a deterministic 0.125 s 440 Hz sine waveform, the
  official 12-frame log-mel features and mask, the SSCP output, both encoder
  layer outputs over three valid soft tokens, the projected audio features, and
  the final normalized 8-dimensional embedding.

The fixture exercises the audio configuration parser, the weight loader
(including finite clipping bounds), two SSCP convolution/LayerNorm/ReLU blocks,
sinusoidal relative positions, chunked attention, light convolution, both
feed-forward branches, the output projection, and the text connection with PLE.
The Rust test compares the mel features, SSCP, both layers, projected features,
and final embedding with absolute/relative tolerances. It runs without the
frozen model cache.

## Model files

Model files are development assets and are not committed. They live in:

```text
.model-cache/<revision>/
```

The directory is ignored by Git. Fetch a file with:

```bash
REV=f9972ac22e696a105c482202646979e33e4b5a1e
curl -sSL "https://huggingface.co/google/embeddinggemma-2/resolve/$REV/config.json" \
  -o .model-cache/$REV/config.json
```

The weights file is about 1.5 GB. Its SHA-256 in the manifest is the Hugging
Face LFS object id:

`197a32965d4b1105faf060417baa899e193fb73cd401f42ec9295234d5553d79`

The text parity test verifies this fingerprint before running. The file is not
needed for the tiny fixture.
